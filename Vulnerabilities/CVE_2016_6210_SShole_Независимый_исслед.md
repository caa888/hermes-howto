# Уязвимость: CVE-2016-6210

## Детали
☁️ SShole . Независимый исследователь обнаружил, что с 2016 года в OpenSSH на дистрибутивах с Musl Linux (Alpine, OpenWRT и других) существует уязвимость : учётные записи, для которых не нужен пароль (например, root, LDAP‑пользователи), принимают любой пароль длиннее 256 знаков. Например, можно войти в систему под учётной записью root, введя строку из 300 символов «A». Причины возникновения ➡️ В 2012 году в Musl изменили поведение функции crypt() : вместо NULL при ошибке она стала возвращать символ *. ➡️ Спустя пару недель в Musl ввели ограничение в 256 байт для паролей в SHA512 - в случае если пароль длиннее, то crypt() возвращает «*». ➡️ В 2016 году в OpenSSH была обнаружена уязвимость CVE-2016-6210 . Она возникла из-за того, что при запросе несуществующего пользователя система тратит чуть больше времени, чем при запросе реального. Разработчики попытались скрыть это, используя соль от другой учётной записи — в том числе от записей с * в /etc/shadow . ➡️ Далее в 2022 году в Alpine Linux блокировку отсутствия пароля для учётной записи root изменили с «&#33;» на «*», что усугубило проблему. Кто подвержен риску ❓ Уязвимы системы, соответствуют нижеперечисленным условиям: ⏺️ SSHD работает на Musl (alpine, openwrt, buildroot, yocto). ⏺️ Не используется PAM. ⏺️ Разрешён вход по паролю. ⏺️ Есть учётная запись с «*» вместо пароля (например, стандартная учётная запись в образах Alpine для AWS и Azure). ⏺️ Присутствует хотя бы одна учётная запись с реальным паролем. ❗️ Рекомендуется обновить OpenSSH до версии 10.6p2 . #news #ssh #crypto 🔗 Все наши каналы 🔁 Все наши чаты 🪧 Для связи с менеджером
