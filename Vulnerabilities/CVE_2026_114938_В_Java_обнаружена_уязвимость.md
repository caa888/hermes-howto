# Уязвимость: CVE-2026-114938

## Детали
🔺 В Java обнаружена уязвимость CVE-2026-114938 с CVSS 4.0–9.2 Она позволяет злоумышленнику без аутентификации и без участия жертвы воздействовать на сервер с Java 17 и новее (включая 21 и 25). Проблема связана с обработкой данных в Java-рантайме. Специально сформированный ввод вызывает повреждение памяти (по одной из версий — в декодере Base64) и может привести к сбою или выполнению команд. Согласно отчетам, затронуты OpenJDK / Oracle Java SE 17.0.6 и новее, а также версии 21, 25, 27. При этом Java 8 и 11 не затронуты, так как в них нет ускоренного декодера Base64. Для срабатывания нужно сочетание условий: 🔵 Железо: серверный x86 с AVX-512 VBMI — Intel Ice Lake+ или AMD Zen 4+. ARM (Graviton, Apple), «Эльбрус», Skylake/Cascade Lake — мимо. 🔵 JVM с флагами по умолчанию (UseAVX, UseBASE64Intrinsics включены). 🔵 Приложение само декодирует недоверенный ввод через java.util.Base64 (getDecoder/getUrlDecoder). Например, заголовок HTTP Basic Authorization до аутентификации. Массовой угрозы нет. Под удар попадают только серверы на свежем железе (Intel Ice Lake и новее, AMD Zen 4–5), где приложение декодирует внешние данные через штатный java.util.Base64 еще до входа. Итог — отказ в обслуживании (DoS), а не выполнение кода. Рекомендуем: 🔵 Провести инвентаризацию Java 17/21/25. Проверить путь исполняемого файла процессов (jcmd <PID> VM.version) и базовые образы контейнеров, а не только java -version. 🔵 Обновиться по мере выхода фиксов (уже доступны: Oracle — 17.0.21.1 , Amazon Corretto — 17.0.21.1.2). 🔵 Проверить Java-сервисы с доступом из интернета и ограничить внешнюю экспозицию с помощью фаервола, security groups и IP allowlist. 🔵 Временно отключить уязвимый путь с помощью флага -XX:-UseBASE64Intrinsics или -XX:UseAVX=2. Пользователям BI.ZОNE WAF уже доступны правила, которые предотвращают попытки эксплуатации, а BI.ZONE EASM поможет найти вендорские Java-приложения.
