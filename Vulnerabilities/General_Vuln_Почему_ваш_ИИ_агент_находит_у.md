# Уязвимость: General Vuln

## Детали
Почему ваш ИИ-агент находит «уязвимости», которых нет Запустить автономный пентест-агент сегодня может любой: 50 строк на Python, пара API-ключей, ночь ожидания. Утром вы получите 94 алерта. Из них 91 — мусор. 28 «SQLi» потому что сервер вернул HTTP 500 на одинарную кавычку. 22 «XSS» с пэйлоадом, который заблокировал CSP. Остальное — публичные CDN-каталоги. Поздравляю, вы стали бесплатным триажером собственной автоматизации. Но три оставшихся алерта — настоящие. Один из них — blind SSRF в API финтех-сервиса, который руками ковырялся бы два дня. Разница между «мусорной пушкой» и рабочим инструментом — в архитектуре. 🔎 Сейчас в open-source больше 39 проектов автономных пентест-агентов. Все укладываются в шесть паттернов, и выбор паттерна важнее, чем количество инструментов в арсенале: • Single-agent ReAct loop — один LLM крутится в цикле «действие → наблюдение → следующее действие». Просто, дёшево, но на сложных задачах проваливается почти полностью. Главный враг — контекстное окно: один вывод nmap -sV -sC на 200 хостов вышибает из памяти всё, что агент нашёл раньше. • Multi-agent planner-executor — планировщик разбивает цель на подзадачи, исполнители работают с чистым контекстом. CHECKMATE, например, генерирует PDDL-описание задачи и отдаёт его классическому планировщику, а LLM только исполняет. Результат — success rate выше на 20% при вдвое меньших затратах по сравнению с Claude Code. • MCP-based — агент подключается к nmap , sqlmap , nuclei через стандартизированные адаптеры, получает структурированный JSON вместо стены текста. Меньше галлюцинаций при интерпретации результатов. ➡️ Самое интересное — цифры из бенчмарков. GPT-4 эксплуатирует 87% one-day CVE , если ему дать описание из адвайзори. Звучит впечатляюще, пока не посмотришь на CVE-Bench: на реальных CVE без подсказок success rate падает до однозначных цифр. На сложных задачах HackTheBox — стремится к нулю. 🎯 Где агенты реально сильны — reconnaissance. Модель анализирует вывод httpx -tech-detect , видит стек [nginx/1.24.0] [PHP/8.1] [WordPress/6.4] и сама решает, какие из 8000+ nuclei-темплейтов прогнать. Не все подряд, а прицельно. Это экономит часы. Но на этапе эксплуатации начинается боль. Модель видит HTTP 500 на кавычку и кричит «SQLi&#33;», хотя сервер просто не обработал невалидный ввод. Без строгих правил верификации вы утонете в ложных срабатываниях. Архитектура, бенчмарки, теневой рынок ИИ-агентов и рабочий пайплайн, выстраданный за полтора года — всё это в полной версии статьи. https://codeby.net/threads/ii-agenty-v-bagkhantinge-orkestratory-i-tenevoi-rynok.96867/
