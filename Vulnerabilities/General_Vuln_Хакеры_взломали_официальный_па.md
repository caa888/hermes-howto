# Уязвимость: General Vuln

## Детали
Хакеры взломали официальный пакет Python Agent Framework от Microsoft на платформе PyPI , опубликовав две вредоносные версии, предназначенные для кражи учетных данных облачных сервисов и другой конфиденциальной информации из систем разработчиков. Microsoft Agent Framework - это инструментарий с открытым исходным кодом от Microsoft для создания агентов ИИ и их координации в рабочих процессах. Это довольно популярный инструмент, который ежемесячно скачивают около 200 000 раз на PyPI . Вредоносные версии 1.26.1 и 1.26.2 были выпущены 17 ноября 2026 года и содержали стилер, который автоматически запускался во время обычного запуска Python в затронутых средах, даже если пакет Agent Framework не был импортирован. Обе версии сохранили зависимость от легитимного пакета agent-framework-core 1.26.0, что позволило фреймворку нормально функционировать, в то время как вредоносное ПО работало в фоновом режиме. Атаку обнаружили и задокументировали сразу несколько ИБ-компаний, в том числе Socket , Step Security и Ox Security . В версии 1.26.1 содержалась программа, которая извлекала секреты из переменных окружения, локальных конфигурационных файлов и других запущенных процессов, где это позволяли права доступа, и нацелена на Azure, AWS, GitHub, Docker, Hugging Face, OpenAI и другие сервисы. Вредоносная ПО также пыталась получить токены доступа к управляемым удостоверениям Azure и токены Azure DevOps OIDC , что потенциально могло предоставить злоумышленникам доступ к дополнительным облачным ресурсам. В версии 1.26.2 добавлены запросы токенов OIDC для GitHub Actions и поиск в каталогах исполнителей GitHub . Согласно Socket и StepSecurity , в первой версии вредоносной ПО agent_framework_meta.pth для кражи учетных данных использовался механизм, запускающийся agent_framework_meta/_telemetry.py во время инициализации Python . Во втором релизе был восстановлен исходный инициализатор пакета, а вредоносный код перемещен в af_runtime_diag.pth и af_runtime_diag.py. Обе версии передавали собранные данные на одну и ту же контролируемую злоумышленником конечную точку https://webhook[.]site/d381fd80-ec62-42ad-8f5c-d1b15103c9bb. PyPI поместил в карантин первую вредоносную версию, но примерно через 2,5 минуты злоумышленник опубликовал вторую версию, которая также была помещена в карантин примерно через восемь минут. Вторая версия указывает на то, что злоумышленник сохранил доступ к публикации после первоначального карантина. Пока остается неясным, как злоумышленник получил доступ к публикации вредоносных материалов в рамках официального проекта Microsoft PyPI. Разработчикам, установившим любую из вредоносных версий, следует изолировать затронутые среды, избегать запуска Python или pip до тех пор, пока они не будут защищены, и выполнить пересборку из заведомо чистой среды, используя безопасную версию 1.26.0. Все потенциально уязвимые учетные данные, которые могли оказаться в пределах досягаемости скомпрометированной среды, следует немедленно заменить. Для определения точного уровня компрометации следователям следует искать конкретный URL-адрес веб-перехватчика в журналах исходящего трафика и отличать заблокированные запросы от завершенных передач.
